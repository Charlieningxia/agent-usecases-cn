让智能体先审智能体写的代码：一轮通过率从 65% 升到 78%（Anthropic 自报）

作者/出处：Anthropic Claude Code 团队（Addy Osmani、Morgan Westlee Lunt、Qing Wang）；小团队改写版作者见 dev.to 原文
原文：https://claude.dev/blog/solving-code-review-at-anthropic/
日期：2026-10-15（Anthropic 原帖）；改写版 2026-10-18 前后 · 工具：Claude Code、 Code Review（托管版）、 REVIEW.md、 GitHub 分支保护与 CI
成本：托管版 Code Review 仅 Team / Enterprise 计划可用，原文未给单价，须显眼标注；本地 /code-review 任意计划可用（按 Claude 用量计费） · 耗时：小团队版落地：必备三层约半天到一天；单写一份 REVIEW.md 约 30 分钟

速览卡

  • 分类：编程搭建
  • 结果：一轮通过率 65%→78%、五轮以上占比 8.9%→1.5%、平均评审轮次 2.08→1.32（Anthropic 自报，未经审计）

一句话

当约 90% 的代码由智能体写出后（Anthropic 自报口径），逐行人审先撑不住的是注意力——他们把评审拆成七层，让机器先筛、人只按风险档位出现，并用三轮上限治住了“评审无限打转”。

原作者怎么做的

  1. 提交前自验：智能体先跑测试/构建/截图对比，再由一个全新上下文的子智能体审 diff——写的人和审的人不共享记忆。
  2. 每个 PR 过 AI 评审：多个智能体并行找问题，验证者投票，只有票数够的发现才贴出来，并标 Important / Nit / Pre-existing；另有可阻断合并的安全评审与全套自动检查（lint、类型、测试、构建）。
  3. 人按风险出现：分类器按改动内容定档——低风险（文档、文案、带开关的新增）自动检查全绿即可合；中风险 1 人；高风险 2 人。智能体的批准永远不算人头，指挥智能体的人算一名评审员，一次批准只对一个提交有效。
  4. 合并队列 + 功能开关 + 分阶段发布，出事靠关开关回滚，不靠紧急发版。
  5. 关键教训：曾有一个 PR 一夜跑了 50 多轮评审。加上“三轮上限”（超过三轮就请作者停下来重想）后，一轮通过率才从 65% 升到 78%（Anthropic 自报）。
  6. 小团队版（dev.to 改写者建议，非 Anthropic 实测）：只抄其中五层，优先级是阻断检查、风险分级、回滚演练；用一份短 REVIEW.md 写清“本仓库什么算事故、每条发现必须给文件行号、最多报 3 条 Nit、哪些路径跳过”。

结果

  • 2026 年 6—9 月，Claude Code 代码库合并 PR 数翻倍以上，同时需要回滚的占比下降 40% 以上（Anthropic 自报，未经审计）。
  • 一轮通过率 65%→78%；需要五轮以上的 PR 从 8.9% 降到 1.5%；平均评审轮次 2.08→1.32（同上口径，无样本量）。
  • 规模背景：其大仓库日落地变更从 5 月约 2,500 涨到 9 月 30,000 以上（同上口径）——这是“为什么必须分层”的背景，不是读者能复现的目标。

提示词结构

（REVIEW.md 起始结构，据原文公开的起始模板提炼，非 Anthropic 内部原文）

「# REVIEW.md ## 本仓库什么算事故：- 收错钱/重复收费 - 返回不属于该用户的数据 - 锁大表的迁移 ## 报告规则：- 每条发现必须给出文件与行号，给不出就丢弃 - 最多报 3 条 Nit，优先报 0 条 - 每条标注：Important / Nit / Pre-existing - 不评论格式，格式归 linter ## 跳过：generated/、快照与锁文件、docs/ ## 必查：auth/、billing/、migrations/、工作流配置；新增环境变量；删测试却没补替代」

中国读者怎么迁移

国内团队用 GitLab/Gitee/自建 Git 同样适用：分层思想与托管产品无关——本地用 Claude Code 的 /code-review 或自有 CI 跑评审 job、把“安全检查 job 必须绿”设为合并门槛、按路径分级人审即可。先只做三件：必填检查、REVIEW.md、一键回滚演练。

风险与限制

  • 全部效果数字为 Anthropic 自报，无样本量、无独立复核，只能当方向、不能当基准承诺；本站引用时必须同屏带状态。
  • 官方文档明说：托管评审本身从不批准或阻断 PR，且“评审无发现”不等于代码无 bug；想要阻断效果必须自己把 CI job 设为必过项。
  • 零人审档位风险真实存在：原帖自承其内部尚缺“指标恶化时自动收紧审批”的熔断，小团队应把低风险定义收窄，并每周抽查自动合并清单。
  • 托管版成本随 PR 量与评审深度涨，原文未给单价，开启前须查官方价格页。
