让智能体每周一自动写经营周报：2 小时手工活变成 4 分钟，3 个月省约 72 小时

一句话

最无聊的重复活最适合先交给智能体：每周一拉数据、算环比、写摘要、发邮件——他把这条流水线自动化后，领导在到办公室前就收到了周报。

原作者怎么做的

  1. 先拆任务：把周报拆成“取数+算术”（不需要判断）和“解读+写作”（需要判断）两部分，只自动化前者的大头，解读部分交给 Claude 生成初稿。
  2. 用 n8n 编排：每周一 8:00 定时触发，依次调用 Mixpanel API 取周活用户数、调用内部 Reports API 取报告下载量。
  3. 把两路数据映射成统一结构，追加写入 Excel 一行，并取出上周同一行，计算两个指标的周环比变化。
  4. 把原始数字、环比和每个指标的业务含义一起发给 Claude，要求写两段平实语言的领导摘要——提示词前后迭代了 4 版才定版，关键是写清读者是谁、要理解什么，而不是只罗列数字。
  5. 把摘要+关键数字通过邮件发给领导层；作者本人不逐期审稿，只保留两个人工触点：收到失败通知时处理、修改提示词后检查首期输出。

结果

  • 单次周报耗时：约 2 小时 → 约 4 分钟（已实现）。
  • 追踪 3 个月：每个周一都准时送达、无需人工干预；团队平均每周省约 6 小时（作者自述）。
  • 年化“300+ 小时”是外推值（6 小时/周 × 约 50 周），原文标题即用此口径；本站引用时标注为外推、非实测全年。
  • 口径提醒：原文对“原来到底花多久”有 2 小时/单次、团队合计约 8 小时/周等不同表述，本条只采用作者在“追踪结果”段落给出的 6 小时/周这一实测口径，其余不引用。

提示词结构

「这是本周的经营数据：[指标名]=[本周值]，上周=[上周值]，环比=[变化%]。请为[领导层]写两段摘要：第一段只说发生了什么变化，第二段说这对[业务目标]意味着什么、值得注意什么。不要罗列全部数字，只引用变化最大的两个；语气平实，不用形容词堆砌；数据缺失时直接写“本周数据未更新”，不要猜测。」（结构据原文第 4 版提示词的描述反推，非原文照录）

中国读者怎么迁移

结构完全可搬：把 Mixpanel 换成友盟/神策/GrowingIO 或自家后台导出，把 Excel 换成飞书多维表格/腾讯文档，把邮件换成企业微信/飞书群机器人。关键动作只有一个——先把“取数算术”和“判断写作”分开，只让智能体碰前者，摘要永远留一个异常通知口子。

风险与限制

  • 数据源 API 一旦改版或口径变更，智能体会照常“准时”发出错误数字；作者的做法是异常通知+改提示词后必查首期，照做时至少加一条“数字超出历史区间就先拦下不发”的规则。
  • 节省时长为作者团队自述、无第三方审计；“300+ 小时/年”为外推，年化数字不要当实测引用。
  • 周报涉及内部经营数据，走外部模型 API 前先确认公司数据合规要求，必要时脱敏或用内部部署。
