一句话

“让智能体读少点、答短点”逐项实测几乎都没用；真正的大降幅来自换分工：找引用、打补丁、跑测试交给本地脚本，模型只审一份准备好的变更并按固定格式回答案。

原作者怎么做的

  1. 先立计量规矩：按整任务计 token（首次 + 全部纠错都算）、与固定基线比、每份产出过质量检查（原测试 + 新增回归测试 + 独立验收 + 人工看 diff）；字节数不算 token、token 不算账单，两条全程分开报。
  2. 逐项测常见招：加固定工作规则（合成后端 36 次运行降 8.58%，但到真实任务上 319,653 vs 319,640 只差 13 个 token）；代码导航工具 Serena（不强制时模型压根不调用，强制先用反而 +75.30%）；过滤测试输出（原始输出缩 70.47%，总 token 只降 3.66%）；回答改短编辑对（输出降 51.88%，总 token 只降 0.56%，因多出来的纠错轮把输入吃回去）。
  3. 再测换分工：本地 TypeScript 工具先找出全部引用并备好补丁，模型只拿相关代码 + 补丁做审查、按 JSON 格式返回完整测试文件，本地协调器落盘、跑检查、失败时把真实失败回送。两项机械迁移（Shopify 域 API 改名、共享定价 API 迁移）先 6 次试点降 75.62%，再 12 次全新运行确认。
  4. 纠错环节单独测：旧纠错提示会把原请求、旧答案、已改文件重复打包；新版每个当前文件只发一次。受控纠错阶段降 28.42%，但放到整任务只有 4.01%（多数任务根本不需要纠错）——两个数都报，不拿阶段数冒充整任务数。
  5. 结论落成 Context Kit 1.0.0 包（本地协调 + 六道“可交付”检查），作者明示：尚未进 AigoPilot 产品、未在新任务上做过实时模型验证。

结果

  • 结构化分工：总 token −87.56%（已实现，作者自测；12 次运行全过预设门槛：总降幅 ≥20%、每项迁移都降、每组配对都胜、质量全过）
  • 同屏拆账：未缓存输入 −8.87%、输出 −25.67%；大头是普通智能体 60 多次工具调用反复重发的缓存输入——87.56% 不是账单降幅，作者明示未测金额与额度
  • 无准备补丁的试点：3 个真实 bug 任务 6 次运行总 token 318,198 → 60,290（−81.05%），但输出 +92.03%、耗时 +38.65%，样本只有每任务 1 组配对，作者只称“小而早的结果”
  • 反面结果同样入账：少给源码在新任务上只降 8.80% 且有一份产出埋了兼容 bug（过了固定测试、改了旧行为），该项被作者判为失败

提示词结构

（按原文的分工与计量法还原，非原文提示词）

```

整任务计量：总 token = 首次 + 全部纠错尝试的输入+输出；先写死通过门槛再开跑。

分工：

  • 本地脚本做机械步：[找全部引用 / 备补丁 / 落盘 / 跑测试]，不经模型；
  • 模型只做判断步：审 [补丁+相关代码]，按固定 JSON 格式返回 [完整测试文件]；
  • 纠错只发一次当前状态：每个当前文件发一份，已生效的旧答案不重发，真实失败输出全量保留；
  • 交付检查分开走：原有行为的兼容测试必须另列，别只测新功能。

报数规矩：缓存与未缓存分开报；阶段降幅不许冒充整任务降幅；token 不许直接写成钱。

```

中国读者怎么迁移

国内团队用 Claude Code / Codex / Cursor 都能搬：先挑一个机械迁移类任务（改名、换 API、批量替换），让本地脚本或编辑器批量重构先备好补丁，再让模型审。计量照抄原文：整任务计、缓存分开、纠错全算。别先去买“省 token 工具”，这 19 项里多数单点招数实测无效。

风险与限制

  • 厂商实验室：作者是 AigoPilot 团队，研究结论正好指向自家待上线方向；虽明示未进产品、未同行评审，引用时保留“作者自测”状态，不升格为独立验证。
  • 87.56% 的适用面很窄：只在两项机械迁移上确认；换成要模型自己找解法的任务，降幅与代价结构完全不同（输出与耗时反而上升）。
  • 模型口径：文中模型为请求口径（gpt-6.1-sol / Codex CLI 0.160.1），日志无法证明服务端实际解析到的模型，作者已自注。
