让智能体替你出差：14 天打猎，newsletter 14/14 期准时发出

作者/出处：Will Gwyn
原文：https://medium.com/@wrg32786/i-went-elk-hunting-for-14-days-and-my-newsletter-didnt-miss-a-day-6c68cea4f8ea
日期：2026-10-29 · 工具：Claude Code、 Claude Code remote control（手机远程接入）、 aigent-os（作者自研开源，context capsule + git-backed 记忆）、 Starlink Mini（太阳能供电）
成本：Claude Code 订阅档位价原文未给；Starlink Mini 硬件价原文未给，复现前须自行核对，订阅价若超 $50/月须显眼标注 · 耗时：搭一套“分工 + 记忆胶囊 + 手机遥控”约半天到一天（已有长期运行基础者更快）；出差期间每天手机 check-in 约 10–20 分钟

一句话

出门打猎 14 天、山里没有手机信号，作者的日更 newsletter 一期没缺：4 个分工的 Claude Code 智能体在家里的电脑上接着干活，他每天晚上只在帐篷里用手机 check-in 10–20 分钟。

原作者怎么做的

  1. 先分工，不搞一个全能智能体：Titus 当总管（盯全局与其他智能体）、Pheme 跑 newsletter、Davinci 负责搭建与修东西、Metis 管派活与杂务；四者共同触达 newsletter、课程、自动头像口播视频引擎、广告 deal、Meta 广告与邮件漏斗。
  2. 用记忆胶囊解决“会话越长越变笨”：作者自研的开源 aigent-os 让每个智能体把上下文存成 context capsule，跑 /clear 清空后从胶囊加 git-backed 长期记忆恢复，而不是让一个会话硬扛两周的上下文。
  3. 手机只当遥控器，不当工作台：通过 Claude Code remote control 在手机 Claude App 里打开家里电脑上的同一个会话、同一批文件；作者强调“不是在手机上干活，而是从手机上指挥干活”。
  4. 每天固定 check-in：打猎回来晚上进帐篷，看 Pheme 当天排好的稿子、问 Titus 期间发生了什么、回答智能体攒下的问题；通常 10–20 分钟。
  5. 留一个人工兜底口子：有天晚上 newsletter 草稿卡住了，作者记不清原因，问智能体后由智能体自行排查修复，当期仍准时发出；作者坦言唯一无法远程处理的是电脑本身出问题（关机、断电、断网）。

结果

  • 14 天外出期间日报 14/14 期准时发出，业务正常运转（已实现，作者自述的连续交付记录，未独立审计）
  • 每天手机 check-in 约 10–20 分钟（作者自述）
  • 一次草稿卡住由智能体自行排查修复，当期仍准时发出（已实现，作者自述）
  • 未给出数字：作者没有给出“比自己坐班省了多少小时”，也不能把 14 期直接换算成省时数；这是本篇主要的口径缺口，成稿时如实标注

提示词结构

（按原文做法还原的运转骨架，非原文逐字提示词）

```

分工先行：[总管] + [内容执行] + [搭建/修复] + [派活杂务]，查问题时先找对口的智能体。

记忆规则：[每个智能体存 context capsule] → [/clear] → [从胶囊 + git-backed 记忆恢复]，不让单会话硬扛长期上下文。

遥控规则：[家里电脑保持开机联网] + [手机只打开同一会话指挥]，不把活搬到手机上做。

每日 check-in 清单：[看当天排好的稿子] + [问总管期间发生了什么] + [回答智能体攒下的问题]。

兜底口子：[草稿卡住先问智能体自查修复]；[电脑本身断电断网只能人工到场]，出发前先确认这条。

```

中国读者怎么迁移

没有 Starlink、没有 aigent-os 也能搬这个循环：用一台家里常开的电脑跑分工智能体，手机远程接入同一会话指挥；关键是先把“记忆胶囊”（定期总结 + 清空重载）和“分工”搭好，否则长会话先变笨、后失控；国内网络与模型接入方式不同，远程接入的稳定性和成本按自己的方案算。出发前务必先做一次“断电断网演练”——确认家里有人能帮你按开机键。

风险与限制

  • 成本口径：Claude Code 订阅档位价与 Starlink Mini 硬件价原文均未给，复现总成本未知；订阅价若超 $50/月须显眼标注。
  • 结果口径：14/14 期是交付记录不是省时数；作者自述未经独立审计；newsletter 已有 9,000+ 订阅者与长期运行基础，新号从零照搬不能默认同样稳定。
  • 单点故障：家里电脑必须保持开机联网，断电、断网、睡眠都只能人工到场处理；这是本篇作者自己点明的唯一硬性前提，出差前必须有兜底人。
  • 与已发布案例的边界：与已发布晨报/周报智能体不同——那几篇讲的是“定时产出内容”，本篇讲的是“长期分工智能体 + 记忆胶囊 + 手机遥控，让业务在主人离线两周时照常运转”；与已发布“智能体替你巡店”不同——彼为单智能体定时巡查，此为四智能体分工协作。
