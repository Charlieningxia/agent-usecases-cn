一句话

一个不会写代码的卢森堡小酒店老板，把同一台家庭服务器上的同一个智能体养了一年：它接电话订房、办下了一家新公司的注册、还把酒店订房做成了能被别的智能体调用的接口——他本人只保留签字、动钱和对外承诺的审批权。

原作者怎么做的

  1. 分工先于工具：智能体可端到端自办的包括调研、写代码、部署到沙箱、测试、监控、文档、起草邮件、数据管道；必须经他本人确认的包括对机构的正式沟通、一切动钱、客户承诺、法律签字、在他个人账号上发布。
  2. 语音前台：电话智能体接真实来电，查空房、报直订价（比 OTA 低 10%，作者口径）、完成订房，并按合规要求宣告通话录音。
  3. 公司注册：智能体起草章程、政府表格、公证协调与注册递交，他本人只签字；新公司 SARL-S 的部级授权已于本月（2026-10）到达（作者自述）。
  4. 订房接口：智能体把酒店订房做成 MCP Server 发布到官方注册表（另上 Smithery 与 Glama），其他智能体可发现并直接订房，佣金 0%（对比 OTA 抽成 15-25%，均为作者口径，未给出实际经此渠道的订房量）。
  5. 自我看护：几十个定时任务与看门狗盯着系统；10 月中 Booking.com 封其服务器 IP 时，监控先发现、智能体一天内换路径重建了管道（作者自述）。
  6. 失败也留档：智能体曾用旧副本部署把生产站回滚、Gmail 令牌被吊销连带半数集成失效、定时任务重复提交险些取消其参赛资格——每件都沉淀成“不再犯”的书面规程，作者称这约 100 条规程才是真正的资产。

结果

  • 三件在产事实（作者自述，凭证公开）：酒店订房站在产收款（Stripe Connect）、公司站在线、MCP 条目在注册表可查；酒店公司自 2005 年在卢森堡商业登记中存在，智能体部分为最近 12 个月所建。
  • 可量化的钱与工时：未给出。直订价低 10% 与 0% 佣金是价格结构，不是已实现节省；实际订房量、通话量、收入变化要等作者系列 Ep.6 的“诚实范围”，本稿不预支。

中国读者怎么迁移

卢森堡的公司注册与 MCP 订房没有直接对应物，但分工法可搬：开网店/民宿/小工作室的人，先把智能体放在“查库存、回常见问、起草对账”这类可留痕的活上，动钱与对外承诺永远留人工确认；失败规程用一个共享文档沉淀即可，不需要先搭复杂系统。
