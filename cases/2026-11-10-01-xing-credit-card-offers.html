让智能体每夜 3 点自动激活信用卡 offer：6 个月 1,700+ 个，Amex 实省 $286.63

作者/出处：George Xing
原文：https://georgexing.substack.com/p/how-i-built-a-bot-that-activates
日期：2026-11-02 · 工具：Mac mini 常驻 + 开源 Browser Use CLI + Codex 智能体（v1）→ Hermes（OpenClaw 系）+ 1Password 凭证库（v2）
成本：Codex/Hermes 订阅价原文未给；Mac mini 为已有硬件，成本未计入；曾试用 CardPointers（$99/年）后认为过剩而弃用 · 耗时：搭建约数小时；跑起来后零人工，每夜自动执行

一句话

George Xing 让智能体每夜 3 点自动登录 Chase 和 Amex，把新出的信用卡 merchant offer 全部点掉激活：6 个月激活 1,700+ 个 offer，Amex 白金卡截图显示实省 $286.63，合计返现“几百美元”——再也不怕 offer 过期作废。

原作者怎么做的

  1. 先试过 CardPointers（$99/年），觉得功能过剩，只想要“自动激活全部 offer”这一个功能，决定自己搭。
  2. v1（Mac mini + launchd 定时）：每夜 3 点 wrapper 脚本 cards-fire.sh 编排全流程——确定性脚本 cards-auth.py 从 1Password 取凭证登录 Chase 和 Amex（凭证与智能体隔离，智能体不碰密码）；Codex 智能体用开源 Browser Use CLI 打开 offer 页逐个点击激活、核对已添加；完成后登出，并发 Telegram 每日汇总。
  3. 解决两个坑：① Browser Use 的 eval 按焦点 tab 执行，Chase/Amex 流程会跑串——自写小脚本 cdp-eval.sh 直连 Chrome DevTools 端口，按域名选 tab；② 银行约 30 分钟无操作就登出，机器人必须每跑登录一次——靠 1Password 凭证库 + 确定性登录脚本解决（2FA 作者称从未触发，推测是设备识别所致，属侥幸，不可依赖）。
  4. v2（2026-09-11 后迁移到 Hermes）：Hermes 凭证库上线（browser_vault_list / browser_vault_fill，智能体经 1Password 登录而不见密码），且 Browser Use 新版 switch_tab(tab_id) 按 tab ID 定位——四个自写组件（cdp-eval.sh、cards-auth.py、cards-fire.sh、3am launchd 任务）全部可以删掉，改由 Hermes 内置 cron 在 3 点触发，智能体全程自理：登录→逐个点击并核对→记录每次点击→登出→发 Telegram 汇总。
  5. v1/v2 两版代码均在 GitHub 公开 repo，可对照。

结果

  • 已节省（作者自述，6 个月实测）：Amex 白金卡页面截图——462 个 offer 已添加，实省 $286.63；作者称 6 个月合计返现“几百美元”（several hundred dollars，未给精确总数）
  • 数字口径（成稿须显眼写清）：1,700+ 个 offer、“面值 $25k+”是 offer 面值，不是省下的钱——成稿不得把 $25k 写成省下的钱；实省以 $286.63（Amex 截图）+“几百美元”合计为准
  • 过程佐证：Telegram 每日汇总截图——2026-10-02 一天激活 6 个 Chase + 76 个 Amex offer；2026-10-30 激活 3 个 Chase + 6 个 Amex；作者发现 Amex 每月 1 号集中放 offer，次日即被机器人扫掉
  • 附赠观察（非结果）：作者文末讨论 offer 机制可能被智能体套利拖垮（Patrick Collison 同款判断），可作风险段素材

提示词结构

（原文无逐字提示词，成稿按流程转写为任务骨架）

```

[每夜 3 点执行：登录 Chase 与 Amex 的 offer 页]；

[把全部未激活的新 offer 逐个点掉，逐个核对状态确为“已添加”]；

[登录与登出由确定性脚本/凭证库处理，智能体不直接接触密码]；

[跑完汇总本次激活数量（分卡、分商家），发 Telegram 给我]；

[遇到 2FA、登录失败或页面结构变化时停下并通知我，别重试蛮干]。

```

中国读者怎么迁移

国内信用卡没有完全相同的 merchant offer 机制，但思路可迁移：各银行 App 里的领券、返现、积分活动同样“不领就作废”，可让智能体定时登录银行网页/App 汇总可领权益、先只读提醒你手动领。注意两点：① 国内银行登录验证更严（短信验证码是常态），全自动登录难度与封号风险比美国更高，先从“只读汇总 + 提醒”做起，别直接自动点；② 绝不要把银行卡密码明文交给智能体，照抄作者的凭证隔离设计（密码库 + 确定性登录脚本，智能体只拿操作权、不见密码）。

风险与限制

  • 结果口径：$25k 是 offer 面值不是实得；实省以 $286.63（Amex 截图）+“几百美元”合计为准；Chase 侧省额未单独给出
  • 合规风险（成稿须显眼标注）：银行自动登录可能违反银行服务条款、有封号风险；作者本人亦写明 2FA 靠设备识别侥幸未触发——换设备、换 IP、银行改风控都可能触发验证导致机器人卡住
  • 成本口径：Codex/Hermes 订阅价原文未给；Mac mini 为已有硬件，成本未计入；成稿不写总成本 $0
  • 适用边界：只适合手里有 Chase/Amex 这类 offer 机制信用卡的读者；offer 本身会改变消费习惯，作者自述刻意不看已激活的 offer 以免多花钱
  • 去重说明：与已发布 2026-10-17-02（Claude 审计信用卡订阅，第一天拿回 $700）不同任务——彼为审订阅，此为激活返现 offer；与已发布 2026-10-17-01（查各州政府无人认领财产库）不同任务；与第 24 批 2026-11-09-03（扫邮箱找待领 payout）同属省钱账单大类但任务不同——彼为扫邮箱，此为每夜自动点 offer
