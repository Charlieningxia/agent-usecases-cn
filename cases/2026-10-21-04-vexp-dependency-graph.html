一句话

编码智能体贵在“找代码”：先用 tree-sitter 把仓库建成依赖图，只把相关节点喂给它，少读整文件，账单立刻降。

原作者怎么做的

  1. 痛点：Claude Code 需要一个函数时也常常把整个文件读进来，上下文越攒越贵。
  2. 做法：写一个 MCP 服务（Vexp），用 tree-sitter 预先计算依赖图（函数、类、类型、导入、调用关系），存 SQLite，文件保存时增量更新；查询时只返回排好序的相关代码节点。
  3. 基准设计（原文口径）：FastAPI 代码库（800 个 Python 文件）、Claude Sonnet 4.6、7 个任务（修 bug、加功能、重构、理解代码），每任务每组跑 3 次，共 42 次执行；两组都用 --strict-mcp-config 隔离，headless claude -p 收集流式 JSON 结果。
  4. 机制变化：基线平均每任务约 15 次 Read + 4 次 Grep + 4 次 Glob；用图谱后平均 2.3 次 pipeline 调用一次拿到排好序的上下文，缓存创建更少、往返更少。
  5. 附带功能：跨会话记忆——观察记录挂到图节点上，代码变了自动标过期。单个 Rust 二进制、纯本地运行，除可选许可证检查外无网络调用。

结果

  • 单任务成本：$0.78 → $0.33，-58%（已实现，作者自测基准，未经独立审计）
  • 时长：170 秒 → 132 秒，-22%；输出 token：504 → 189，-63%（同上口径）
  • 分任务类型：理解代码 -57%、新功能 -53%、重构 -48%、修 bug -29%（同上口径；作者自释：bug 修复范围本来就窄，省得最少）
  • 样本量提醒：7 个任务 × 3 次 × 2 组 = 42 次，单个代码库、单个模型，不许外推成普遍降幅

中国读者怎么迁移

国内团队用 Claude Code、Cursor、通义灵码等都会遇到“读全仓烧 token”。图谱法与工具无关：先给仓库建一份符号/依赖索引（tree-sitter 是开源的），让智能体先查索引再读文件。先在一个 500+ 文件的老仓库上按上面的协议复测半天，数字对得上再推广。
