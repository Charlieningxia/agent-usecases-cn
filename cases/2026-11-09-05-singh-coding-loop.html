让智能体自主循环写代码：周期 3.5 小时→38 分钟

作者/出处：Sumit Singh
原文：https://medium.com/@ssilu07/how-i-replaced-80-of-my-daily-coding-workflow-with-claude-code-cli-and-custom-hooks-9b578475d301
日期：2026-11-01 · 工具：Claude Code CLI（claude -p）、 150 行 Python 状态机 agent_runner.py、 pytest、 AST 校验
成本：单 PR 平均 $0.31 tokens；Claude 订阅/套餐价原文未给 · 耗时：脚本本身一天可跑；背景是 4 个月团队迁移，不是“一天建成整套流水线”

一句话

Sumit Singh 的团队弃用 CrewAI（800 行定义、$45 没解出一票），改用 Claude Code CLI + 150 行确定性 Python 状态机做自主循环：两个工程团队 120 张票、30 天生产数据，bug 修复与脚手架平均周期从 3.5 小时降到 38 分钟，单 PR 成本 $0.31。

原作者怎么做的

  1. 先试 CrewAI 两周：800 行 agent 定义、循环委派，$45 API 账单没解出一张票——弃用。
  2. 改用 150 行确定性 Python 状态机 agent_runner.py（原文全文附代码）：Claude Code CLI（claude -p）跑任务 → AST 校验 → pytest 沙箱跑测试 → 失败把报错喂回 agent 最多重试 3 次 → 通过则 git 提交 PR，失败则回滚。
  3. 护栏是血泪换来的：v1.0 因 5 秒超时误判，把数据库迁移文件重写、600 行业务逻辑改成 nonsense，4 小时排障后收紧为 45 秒超时 + 禁写迁移/.env/生产配置/密钥目录。
  4. 另外三条生产教训：上下文窗口一次读 25 个文件会掉质量（限文件数或 AST 切片）；无确定性停止条件会无限重构循环；测试套件必须 100% 确定、mock 掉网络 IO，否则 agent 会把 flaky 测试当成代码 bug 重写。
  5. 分支隔离：永远不在 main 或共享分支上跑 agent，用 git worktree 开临时分支。

结果

  • 已节省（作者自测，团队 30 天生产数据，120 张票）：脚手架新端点 45 分钟→8 分钟（5.6x）、单测覆盖生成 30 分钟→4 分钟（7.5x）、flaky 测试调试 60 分钟→14 分钟（4.2x）；bug 修复/脚手架平均周期 3.5 小时→38 分钟；单 PR 平均成本 $0.31（tokens 2,100→14,200）
  • 诚实失败：v1.0 凌晨 2 点重写迁移文件、EC2 CPU 99.8% OOM，4 小时排障——护栏不是可选项，是生存装备
  • 标题“替换 80% 日常编码工作流”为作者 headline，表中无直接对应的 80% 口径——成稿须标注

提示词结构

（本条的可复用物是 agent_runner.py 的状态机骨架，非原文逐字代码；完整 150 行脚本见原文）

```

[任务提示词] → [claude -p 跑任务] → [AST 校验 + pytest 沙箱（45 秒超时，--maxfail=2）] → [失败 → 把报错喂回 agent，最多 3 次] → [通过 → git 提交 PR；失败 → git checkout . 回滚]；

[禁写路径：.env、migrations/、alembic/versions、config/production.json、secrets/]；

[分支隔离：git worktree 开临时分支，绝不在 main 跑]。

```

中国读者怎么迁移

这是给有测试套件的开发者的“自主循环”范本：别堆多智能体框架，150 行确定性代码 + 测试反馈循环就够。国内读者照做时注意两点：① 前提是你有 pytest/vitest 这类自动化测试套件，没有测试兜底就别放 agent 自主跑；② 先在 worktree 临时分支上试，禁写清单（.env、迁移文件、生产配置）先写死再开跑——作者 v1.0 的凌晨事故就是没做这两步。
