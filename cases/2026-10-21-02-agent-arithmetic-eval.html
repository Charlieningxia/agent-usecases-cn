一句话

别先上复杂的模型评测：先用几十行代码检查智能体报告自己跟自己对不对得上，很多低级错误根本过不了算术关。

原作者怎么做的

  1. 素材来自 AI Engineer 2026-10-17 的研讨会 “How to Know If Your AI Agent Is Any Good: Evals With Phoenix & Claude”（讲者 Laurie Voss，Arize AI）：用 Claude Agent SDK + Claude Haiku 4.5 搭了一个股票报告智能体，仓库 seldo/aie-nyc 保存了 16 次运行记录。
  2. 问题样本：其中一次运行写出分析师评级分布“50% 买入、52.6% 持有、13.1% 卖出”，三者相加 115.7%——而研讨会自带的代码评测放行了这份报告，人工标注还给了“可执行（actionable）”。
  3. 作者写了一个 86 行 Node 脚本，只做一件事：检查报告对自身数字的陈述是否自洽（原文称 checks the arithmetic a report states about itself）。
  4. 在 16 次保存运行上跑这个脚本：共找出 5 处矛盾，全部出在同一次运行里。
  5. 运行条件：不需要 API key、不需要 Phoenix 服务，约 5 分钟跑完（作者原文口径）。

结果

  • 115.7% 的评级分布被原评测 + 人工标注双双放行（已实现，仓库保存数据）
  • 86 行脚本找出 5 处矛盾 / 16 次运行（已实现，可按原文方法复算）

提示词结构

本条的核心资产不是提示词，而是检查清单结构（按原文方法还原）：

```

对智能体的每一份报告，先跑代码检查，再谈内容质量：

  1. 报告里所有“占比/分布”加总是否等于 100%（允许 ±[0.5]% 舍入）
  2. 报告里引用的总数与分项之和是否相等：[总数] = Σ[分项]
  3. 同一数字在标题、摘要、正文三处是否一致

任一项不过 → 整份报告打回，并记录是哪一次运行、哪一条检查

（不要让写报告的同一个模型来做这项检查，用确定性代码）

```

中国读者怎么迁移

任何让智能体出“带数字的报告”的场景都能直接搬：周报、竞品分析、财务汇总、客服质检。先花半小时把“加总、占比、总数对分项”三类算术检查写成脚本挂在报告生成之后，比先买评测平台便宜得多，也更容易向老板解释为什么打回。

风险与限制

  • 算术自洽 ≠ 内容正确：分布加起来等于 100%，数字本身仍可能是编的；这只是第一道最便宜的门，后面仍需来源核对与人工抽查。
  • 样本只有 16 次保存运行、且全部来自一个研讨会演示智能体，不许外推成“所有智能体报告的错误率”。
