让智能体替一人重建整个平台：8 个月、7,000 万 tokens、自己零写提示词

作者/出处：Dean DiCarlo
原文：https://newsletter.aicollective.com/p/seventy-million-tokens-zero-prompts
日期：2026-11-03 · 工具：Claude Code
成本：约 $200/月 AI 订阅 + <$100/月托管、数据库与其他工具，合计约 $300/月——远超 $50/月线；上月 7,000 万 tokens 按 API 价约 $5,400（订阅价覆盖，未实付） · 耗时：作者用 8 个月重建整个平台；读者照做只能取方法论，无法一日复制规模

一句话

公司没钱了，创始人 Dean DiCarlo 干脆一个人从零重建整个房产平台：旧版是团队花数年、数十万美元做的；重建花了 8 个月、每月约 $300，他自述“比原版更好”——上个月 7,000 万 tokens 流过 Claude Code，而他本人没给编码会话写过一条提示词。

原作者怎么做的

  1. 双循环分工：他每天花几小时和一个独立的“策略会话”对话——这个会话当项目经理兼架构师，负责想清楚建什么、哪里坏了、下一步做什么、愿意接受什么取舍；谈妥后由它写出给编码会话的工单，他当“快递员”把工单搬过去，Claude Code 执行完，他再把结果搬回策略会话复盘、做下一个决定。
  2. 决策写进仓库，不只留在对话里：平台有需求文档、技术规格、构建计划、决策账本；规则变了就记下“旧规则被哪条新规则取代”；两处记录冲突时写明哪份赢。8 月的日志显示，AI 每写 1 个 token 就要读约 350 个——“你让它读什么，就是工作本身”。
  3. 智能体只推理、不直接动生产库：以 Lennie（研究）与 George（写 outreach）为例，AI 可以推理 messy 的信息，但关键动作走编排层——AI 用结构化形式提需求，受信任的工作流校验后只碰它被允许碰的部分，返回必需的结果；对外发送一律人工批准。
  4. 失败变“绊线”而非新规则：每次发现一类失败，不写“下次记住别这样”，而是建一个永久自动检查。著名的三则教训：① 信鸽角色 JET 的功能测试全绿，但生产库里根本不存在 JET 这个角色——测试自己种下了它要找的证据；② 夜间维护进程写了一份漂亮的报告（数万条记录已审阅、收尾干净），其实它什么都没干——一个算术错误让它以为没活了，报告读的是上一次运行留下的结果文件；③ 官方安全检查在另一台服务上跑，全部 119 次运行都失败了，三周没人打开过那页，本地机器上全绿让人误以为健康。
  5. 定期“审计自己的文档”：他开过一次 AI 审计会话，任务就是不信任项目自己的文档，结果发现一本规则手册已经过期、一份 bug 报告里一句猜测被悄悄记成了事实——都在变成代码之前几分钟就改掉了。

结果

  • 已实现（作者自述，附日志图）：一人 8 个月重建整个平台（房产分析引擎、消费者游戏、outreach 系统、数据管道、部署，全部重做、零复用），自述比旧版更好；旧版是团队数年 + 数十万美元
  • 上月约 7,000 万 tokens 经 Claude Code；按 API 价约 $5,400，实际走订阅未实付；作者本人零条提示词直接发给编码会话
  • 诚实失败三则（见上）：JET 信鸽测试全绿但生产库无此角色、夜间报告描述的是旧运行结果、119 次官方安全检查全部失败且三周无人看
  • 成本实测：约 $200/月 AI 订阅 + <$100/月托管等，合计约 $300/月——远超 $50/月线，成稿已显眼标注；这不是一个便宜的方案

提示词结构

（按原文方法论还原的任务骨架，非原文逐字提示词）

```

双循环：[策略会话：项目经理 + 架构师，想清楚建什么、哪里坏了、取舍是什么，输出带验收标准的工单] → [人当快递员：把工单搬给编码会话] → [编码会话：Claude Code 执行] → [人把结果搬回策略会话：复盘实际发生了什么，再定下一步]。

决策账本：[需求文档 / 技术规格 / 构建计划 / 决策账本全部写进仓库]；[规则变了就记下旧规则被哪条取代]；[两处记录冲突时写明哪份赢]；[编码会话只收具体工单 + 验收标准，不让它从几个月历史里自己拼]。

权限边界：[智能体只推理，不直接动生产库]；[关键动作走编排层：AI 提结构化需求 → 受信任工作流校验 → 只碰允许的部分 → 返回必需结果]；[对外发送一律人工批准]。

失败处理：[每类失败建一个永久自动检查（绊线），不只写一条新规则]；[代理法则：能查实物就不查替身——测试不许自己种下它要找的证据]；[定期开一次“不信任自己文档”的审计会话]。

```

中国读者怎么迁移

这篇的价值是方法论，不是“8 个月重建平台”本身——普通读者复制不了这个规模。能直接抄走的是四条：① 把“想清楚”与“写代码”分到两个会话，中间由人搬运工单；② 决策写进仓库里的文档，而不是只留在 AI 的上下文里（上下文是工作记忆，仓库才是制度记忆）；③ 智能体只推理、受控系统才执行，对外动作人工批准；④ 每次失败变成一个永久自动检查，而不是一句“下次注意”。国内读者用 Claude Code、Codex、通义灵码等同理，成本口径要按自己的订阅重算——每月约 $300 不是小数目。

风险与限制

  • 成本口径：约 $300/月（$200 AI 订阅 + <$100 托管等），远超本站 $50/月线，一般读者照搬不起；上月 7,000 万 tokens 按 API 价约 $5,400，订阅价覆盖不等于免费
  • 适用边界：8 个月、一人、全职投入的重建工程，不是周末项目；方法论可取，规模不可一日复制；作者本人有编程基础（自述“不是明星开发者”）与金融合规背景（前 FINRA 持牌经纪商负责人），决策账本那套纪律来自职业习惯
  • 结果口径：全部数字为作者自述 + 会话日志图，未独立核实；“比原版更好”是作者自评，无第三方对照
  • 来源口径：本文刊于 AI Collective Newsletter《The Byte》（编辑 Josh），作者 Dean DiCarlo 为客座作者，文末有作者介绍（Homing 创始人、前 LTVtrade 创始人）
  • 安全提醒：作者自承审计仍发现过硬编码凭证——凭证管理、密钥外置、重试幂等这些坑，照搬前先按他的绊线清单自查
